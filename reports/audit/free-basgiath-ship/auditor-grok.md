### Root cause
The signet beat is wired to the wrong interaction event. `afterEvents.playerInteractWithBlock` means "the block accepted the use." A lodestone accepts a compass. This map's player has an empty hand. The quiz function itself is fine, so the syntax check and the release script stay green. The same test gap hides the armor-stand clock: the build origin is a falling entity, and the college is applied one stage per tick.

### Confidence
medium — a Bedrock 26.20 client would change this. If an empty-hand use on a lodestone fires `afterEvents.playerInteractWithBlock`, drop the critical row. If the armor stand's Y stays inside one block from the summon through stage 7, drop the gravity row. The tie counts and the format-version mismatch do not need a client.

### Unique angle
The fresh world always lifts the player to exact Y=80 before the anchor exists. One gravity step then changes which block column every later `~` command uses. The span is split across three ticks on purpose. A text search for `32768` and `lodestone` cannot see that clock.
