## Body

### The test bench — the highest-leverage idea in this wave

Three repos combine into something we do not have: a way to verify Basgiath **without a human at the keyboard.**

| Repo | Role |
|------|------|
| `bedrock-mc/mcpelauncher-agent` | Drives a running Bedrock client through MCP |
| `itzg/docker-minecraft-server` | Headless container lifecycle for world-gen and pack validation |
| `dadeeen/MCBE_Inventory_Editor` | Reads and writes Bedrock **LevelDB player NBT** offline |

Together: set an inventory without launching the client, boot the world headlessly, assert the loadout, repeat. That is the difference between testing dragon-flight behaviour by hand and testing it in CI.

**Suggested first step.** Not all three. Start with the container plus the NBT editor — that pair needs no agent and no client automation, and it already removes most manual clicking.

### Player identity — the one Integrate row

`thejacedev/McHeads-API` (MIT) renders isometric heads, 3D body renders, and raw skins from **Bedrock XUIDs as well as Java UUIDs**. Legacy skin renderers are Java-only, so this covers a real gap for flight scoreboards, rider profiles, and Discord embeds.

### The layout pattern

`rehan-remade/universal-modder` — MIT, 2,919 stars, pushed the day it was checked. It ships **one canonical `skills/` tree** with `.agents/skills`, `.claude/skills`, `.gemini/skills`, `.github/skills` all symlinked to it, a single canonical `AGENTS.md`, and a `knowledge/INDEX.md` field-notes base where the agent must record what it learned for the next agent.

**Adopt the layout, not the pipeline.** Its asset generation routes through a paid third-party service. The skill tree costs nothing to copy.
